## Google — Photos Library API + Gmail API 🟡 (Milestone 3 — code shipped, needs Google creds to go live)
- **Scopes (read-only):** `photoslibrary.readonly`, `gmail.readonly`.
- **Flow:** OAuth handled **server-side** in the `google-oauth` Edge Function; tokens stored in `oauth_tokens` (RLS deny-all → server-only), refreshed server-side. The client never sees them.
- **Import function (`import-photos`):** returns a `jobId` immediately and runs in the background (`EdgeRuntime.waitUntil`); pages the library, stores **metadata + thumbnail URL** (never originals), computes an **average-hash (aHash)** for dedupe. **Rate-limit aware** (429/503 backoff) and **resumable** (paging cursor persisted in `import_jobs.cursor`).
- **Testable now without Google:** `import-photos` `mode=sample` imports a small placeholder library (with intentional duplicates to prove dedupe) into your real DB and drives the live scan progress. **Deployed + live** on the project.

### To enable the REAL Google path
1. Google Cloud Console → new project → enable **Photos Library API** (+ **Gmail API**).
2. OAuth consent screen (External, "testing" mode is fine to start; add yourself as a test user).
3. Create an **OAuth client (Web)**; authorized redirect URI = the `google-oauth` function URL.
4. Set function secrets: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `OAUTH_REDIRECT_URL`, `APP_REDIRECT_URL`.
5. Production needs Google's **verification review** for these sensitive scopes before public launch.

> ⚠️ **Reality check:** Google restricted the Photos Library API in 2025 — `photoslibrary.readonly` now generally only returns media your app created; reading a user's whole library may require the new **Photos Picker API** (user selects what to share). Our `PhotoSource` abstraction isolates this; swapping the Picker in is a contained change. Gmail attachment import is scaffolded as a follow-up.

## Anthropic — Claude API 🟡 (Milestone 4 — code shipped; key needed for AI mode)
- **Server-side only**, in the `organize-photos` Edge Function. **Deployed + ACTIVE.**
- Model **`claude-opus-4-8`**, Messages API via `fetch`, **structured JSON output** (`output_config.format` with a `json_schema`) so clustering returns validated `{albums:[{title,type,badge,photo_indices,best_shot_indices}]}`.
- **Uses (M4):** cluster photos into events/trips/people/pets, pick best shots, label albums. Idempotent + re-runnable (clears AI albums, rebuilds). Product copy + gift suggestions are M5.
- **Two modes:**
  - `mode=heuristic` (default) — deterministic clustering, **no key needed**, testable today. Produces real albums in your DB.
  - `mode=ai` — real Claude clustering. Set the function secret `ANTHROPIC_API_KEY`, then call with `mode:'ai'`. Falls back to heuristic automatically if the key is missing or the call fails.
- **To enable AI mode:** Supabase Dashboard → Edge Functions → `organize-photos` → Secrets → add `ANTHROPIC_API_KEY` (from console.anthropic.com). Cost is pay-per-use.
- **Cost control:** sends compact photo metadata (not full images) for clustering; cache + idempotency keep re-runs cheap. Production can add image blocks + faces/EXIF for richer reasoning.

## Gelato — print fulfillment 🟡 (Milestone 5 — code shipped; key needed for real orders)
- Behind a **`PrintPartner`** interface in the `create-order` Edge Function (so Printful/Prodigi/Printify can be swapped). **Deployed + ACTIVE.**
- **Operations:** `createDraftOrder` → price + shipping + optional hosted-checkout URL; the order is recorded in `orders` with the partner + `partner_order_id`.
- **MockPartner** (default, no account) returns a computed price so checkout completes end-to-end and records the order. **GelatoPartner** activates when `GELATO_API_KEY` is set (scaffolded — real order creation needs Gelato product-UID mapping + print-file upload; documented inline).
- Product suggestions are generated by `suggest-products` (deployed): one product per top album, with copy from **Claude `claude-opus-4-8`** (`mode=ai`, structured output) or templates (`mode=heuristic`, default).
